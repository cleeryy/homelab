Last synced with live infrastructure: **September 2026**.

The VM list is short on purpose: virtual machines are reserved for the heavyweights — full operating systems with passed-through disks (TrueNAS), the firewall itself (OPNsense), and the legacy Docker hosts that predate the LXC era. Everything that can be a container already is one, which is exactly why this page fits on a screen while the container inventory does not. Where containers carry one service each, each VM below carries a whole Docker environment or a network function that needs a kernel of its own.

## `pve1`

The `pve1` virtual machines are the legacy application tier that never had a reason to move. They sit on the flat management LAN rather than on VLANs, each one hosting a Docker stack that predates the current LXC-first placement, from small web apps through Nextcloud to monitoring and automation. Their modest RAM allocations reflect that history: they were sized when `pve1` was the only host, and they have stayed put because they are stable.

## `pve3`

The `pve3` virtual machines are fewer in number but far heavier in responsibility. TrueNAS owns the physical disks, OPNsense owns the network, and three Docker hosts carry the entire media pipeline, while a small crowd of stopped machines preserves past experiments and a standby firewall. Anything stopped here is stopped for a reason, and the standby firewall in particular should never be started casually.

Start-at-boot and boot order for all of the above: [Operations > Startup & shutdown](/operations/startup-shutdown).

The stopped rows repay careful reading. The OPNsense standby is a full clone kept powered off with fresh MAC addresses, so booting it without preparation would duplicate the master on the same networks. The `taoxd` and `lune` machines are preserved experiments rather than active services, and the Mint desktop floats on DHCP in the admin VLAN. Cross-check media hosts against [Service placement](/architecture/service-placement) before moving any of them.

## ID ranges currently in use

The numbering scheme grew alongside the cluster, so it reads as history as much as policy. Legacy VMs from the earliest days occupy `100–199`, with only `105` remaining, while `200–299` holds the Docker host VMs for general application workloads and `300–399` holds their counterparts for the media stack. Edge and network functions live in `500–599`, where `501` is the OPNsense master and `502` its standby. Three assignments fall outside that tidy progression for historical reasons: `127` predates the per-role ranges and stays with TrueNAS, `6000+` marks POC machines, and `10000+` marks lab desktops. New VMs are expected to follow the role-based ranges rather than reuse retired IDs.

## OS notes

The Docker host generation is uniform in a way the container fleet is not. Those hosts run Ubuntu 24.04, with LTS point releases 24.04.2 and 24.04.3 observed across the fleet at the last sync. One reporting quirk is worth knowing so it does not cause confusion later: the Nextcloud host reports its OS line in Beszel as `6.8.0-111-generic`, which is a kernel string, while the Ubuntu release line is not captured in the same place. Kernel and distribution versions therefore come from different lenses and should not be compared directly.
