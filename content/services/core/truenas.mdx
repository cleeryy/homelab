TrueNAS is the exception that proves the migration: while everything else moved to VLAN 20/50, the storage VM stays on `192.168.1.74` (`vmbr0`) with passed-through disks, because both Proxmox NFS storages and in-guest `/mnt/medias` mounts point at LAN addresses. Moving it buys nothing and risks every mount in the fleet.

## Placement

The VM stays on the LAN bridge on `pve3` by design, with physical disks passed through and the guest agent running.

- VM `127` on `pve3`, `192.168.1.74` (vmbr0). QEMU guest agent running.

## Status

TrueNAS is running and its exports are consumed both as the Proxmox `truenas` storage and as guest NFS mounts. VLAN 20 reaches it through OPNsense, following the same path as the physical NAS.

## Dependencies

The only dependency is hardware: the passed-through physical disks the pools live on. Slot-to-disk mapping is unknown (see the nodes gaps), so any disk surgery starts with identification rather than replacement.

## Failure impact

If TrueNAS stops, NFS-backed guests lose their media and storage mounts until it is restored, while VM virtual disks living on `nas` are unaffected. The blast radius is therefore large for media but narrow for the platform itself.

## Known gaps

Which physical disk sits in which slot, and the TrueNAS pool and dataset layout, are not recorded here. A short hardware-to-pool map would close both at once.
