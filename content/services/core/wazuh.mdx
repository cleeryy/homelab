Last synced with live infrastructure: **September 2026**.

The firewall sees packets; Wazuh is supposed to see stories. Suricata and CrowdSec on OPNsense react in real time at the edge, but they cannot tell you that a host started behaving strangely three days ago — that is the SIEM's job, once agents report in. Today Wazuh is deployed and reachable but young: the dashboard is up, the agent fleet is not yet inventoried, and alerting is still to be defined. Treat this page as a construction site with a clear direction rather than a finished reference.

## Placement

Wazuh runs as a single generously sized LXC on `pve3`, where it can receive agent traffic from the internal hosts once enrollment begins.

| Kind | ID | Name | Host | Function |
|------|----|------|------|----------|
| LXC | `129` | `wazuh` | `pve3` | SIEM (8 GB RAM) |

## Status

The dashboard is up and reachable through Caddy over TLS with backend verification skipped, but no SSO gate fronts it yet. Agent deployment across internal hosts is the expected next step, and the enrolled-agent inventory is still pending.

- `wazuh.cleeryy.cloud` → Caddy → `https://wazuh:443` (`tls_insecure_skip_verify`). No SSO gate currently — hardening tracked in the [migration plan](/architecture/migration-plan).

## Dependencies

Wazuh needs its agents and Caddy rather than any platform database: agents must be able to reach it, and operators reach it through the reverse proxy. It sits alongside OPNsense Suricata and CrowdSec as central security monitoring, not as a replacement for them.

## Failure impact

If Wazuh goes down, the homelab loses centralised security visibility but nothing else changes: there is no production traffic impact. The edge controls keep reacting on their own; what disappears is the ability to correlate across hosts and time.

## Known gaps

Almost everything that would make Wazuh real is still ahead: no enrolled-agent inventory, no alert rules, no notification channel, no retention policy — and the dashboard itself sits behind no SSO. This page is honest about that on purpose. The next step is a single evening: enroll five hosts, define three alerts, wire one notification, then document what was done.
