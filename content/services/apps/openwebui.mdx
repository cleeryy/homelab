Last synced with live infrastructure: **September 2026**.

This is the friendly face over whatever language models the homelab talks to: one chat UI in the browser instead of API keys scattered across laptops. The frontend itself is stateless and boring; all the security and cost questions live in the backend provider it points at — which model, whose API key, who gets billed. That is why the pending list on this page is dominated by provider wiring and SSO rather than by the container, which more or less runs itself.

## Placement

OpenWebUI runs as LXC `131` (`openwebui`) on `pve3` on the production VLAN, carrying the `10.1.20.31` tag with 8 GB of RAM.

## Ingress

Traffic arrives as `chat.cleeryy.cloud` through Caddy toward `openwebui:8080`, currently with no SSO gate — a combination worth revisiting for any AI frontend that holds API keys, since SSO is recommended here.

## Dependencies

The only dependency that matters is the backend model provider, and it is not captured here. Whether inference is local or a hosted API determines the real failure domain, the cost exposure, and whose key is at stake — the container itself is the least interesting part of the chain.

## Failure impact

A `pve3` outage takes the frontend down with it, but hosted-model usage from other clients continues unaffected. The frontend is a convenience layer, not the model itself.

## Known gaps

The backend provider wiring (local versus hosted, whose key, who pays) is undocumented, the SSO decision is open despite API keys being involved, and the backup posture for chats and settings is unknown. The first item is the one to resolve; the rest follows from it.
