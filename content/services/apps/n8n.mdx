n8n is where the homelab stops being a collection of apps and starts behaving like a system: workflows that glue services together, react to events, and run while everybody sleeps. That power comes with two obligations documented nowhere else on this site. First, the credential store — every API key n8n holds, protected by an encryption key that must survive host rebuilds. Second, silent failure: a broken workflow does not page anybody, it just stops doing its job. If something "used to happen automatically" and doesn't anymore, look here first.

## Placement

The automation host is VM `204` (`ubuntu-n8n`) on `pve1`, carrying the Beszel label `n8n` at IP `10.1.20.47`. Beszel reports the system hostname as `ntfy`, which does not match the Beszel label or the Proxmox VM name — a cosmetic mismatch recorded here so operators do not misidentify the host.

## Docker containers

The stack pairs the automation app with its own internal reverse proxy, plus the usual management sidecars. `n8n-compose-n8n-1` is the application itself, fronted by `n8n-compose-traefik-1`, while `portainer` and `beszel-agent` provide management and monitoring and `watchtower` keeps images moving.

| Container | Function |
|-----------|----------|
| `n8n-compose-n8n-1` | n8n application |
| `n8n-compose-traefik-1` | Internal reverse proxy in front of n8n |
| `portainer` | Container management UI |
| `watchtower` | Image auto-update |
| `beszel-agent` | Monitoring agent |

Because `watchtower` periodically updates images, recovery procedures should never assume pinned tags. Workflow and credential state lives in the n8n container's local data directory, which makes that volume — and the encryption key protecting it — the backup weak point of the whole host.

## Dependencies

Traffic enters via Caddy as `n8n.cleeryy.cloud` toward `https://10.1.20.47:443` (backend certificate not validated) and then hits the stack's own Traefik. All n8n state, workflows and credentials alike, is stored locally in the n8n container's data directory rather than in any shared service.

## Operational notes

`watchtower` keeps the images rolling, so version drift between documentation and reality is expected. The `ntfy` hostname mismatch is noted purely to avoid confusion when reading Beszel.

## Failure impact

A `pve1` outage takes the whole n8n host with it, and every workflow stops at once. Worse than the outage is the failure mode when only a downstream API is unreachable: affected workflows fail silently instead of alerting, so the symptom surfaces as "automation quietly stopped" rather than an error.

## Known gaps

The encryption key for the credential store is the standout unknown — lose the host without it and every workflow credential is scrap. The data-volume backup path matters for the same reason, while the `ntfy` hostname mismatch is cosmetic by comparison. Resolve them in that order.
