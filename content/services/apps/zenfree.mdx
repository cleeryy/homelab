ZenFree est un proxy de pool (binaire Rust `zenfree`, image `zenfree:test`) devant l'API gratuite opencode Zen (`https://opencode.ai/zen/v1`). Il fait tourner les sorties sur 3 VPN (gluetun : se-1, ch-1, nl-1) avec rotation quand un plafond par IP est atteint. 84 modèles gratuits, coût 0.

## Placement

- LXC `233` `zenfree` sur `pve3`, `10.1.20.33` (VLAN 20), stack docker-compose dans `/opt/zenfree/deploy/`.
- Écoute `:8020` (LAN uniquement, pas d'ingress Caddy).

## Interface

- Compatible OpenAI : `GET /v1/models`, `POST /v1/chat/completions`, `POST /v1/responses`.
- Auth : Bearer obligatoire (`auth.enabled: true`). Token dans `/opt/zenfree/deploy/zenfree-pool.docker.yaml` (clé `tokens`, ligne 9) — le lire sur place, ne jamais le copier en clair ailleurs.
- Les réponses sont gzippées : utiliser `curl --compressed`.

## Consommateurs

- Hermes profil `opencode` (Discord) : provider `zenfree` (`~/.hermes/profiles/opencode/plugins/model-providers/zenfree/`), `base_url http://10.1.20.33:8020/v1`, modèle `space-bunny-free`, clé `ZENFREE_API_KEY` dans le `.env` du profil. Repli : `stealth/space-bunny-alpha` via OpenRouter.
- OpenWebUI (CT 131) : **via le traducteur** `http://10.1.20.41:8099/v1` (clé dans `/home/hermes/zenfree-translator/.key`, à lire sur place), pas direct au pool. Modèles : `muse-spark-1.3-contributor-free`, `space-bunny-free`, autres en retransmission.
- Appels directs compatibles OpenAI : uniquement `space-bunny-free` passe en direct au pool ; muse exige la recette responses (voir traducteur).

## Traducteur muse (`zenfree-translator`, CT `hermesagent` 10.1.20.41:8099)

- Le pool seul ne fait pas passer muse (500/403 : il casse la recette d'empreinte). Le traducteur (`/home/hermes/zenfree-translator/translator.py`, service user systemd `zenfree-translator`, enabled) traduit `POST /v1/chat/completions` → `/v1/responses` amont avec : endpoint responses, `stream: true`, `store: false`, session `ses_`+requête `msg_` valides et stables par clé, quartet d'outils `bash/glob/grep/read` + `tool_choice: auto`, `max_output_tokens >= 16`, headers `opencode/1.18.31` + `x-opencode-*`, `Bearer public`.
- Muse part en direct amont (même egress que le vrai client) ; le reste passe par le pool (rotation VPN + catalogue).
- `GET /v1/models` retransmis du pool (84 modèles). Concurrence : sémaphore à 3, sessions stables par conversation (dérivées du premier message : continuité + quota, conversations différentes en parallèle), 429 amont retransmis tel quel (retry côté client). Streaming SSE supporté (agrégé en un chunk + `[DONE]`).

## Opérations

- Config montée en bind (`/etc/zenfree/config.yaml`) : après modif, simple `docker restart zenfree` suffit.
- Rotation/fallback inter-sorties automatique ; en voir l'état via `docker logs zenfree` (`member unreachable` = sortie KO, `proxied ... status=200` = OK).
- Limites connues : quotas par IP côté Zen (files d'attente possibles), certaines sorties parfois injoignables (couvert par rotation). Pas fait pour du gros parallèle.
