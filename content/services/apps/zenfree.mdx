ZenFree est un proxy de pool (binaire Rust `zenfree`, image `zenfree:test`) devant l'API gratuite opencode Zen (`https://opencode.ai/zen/v1`). Il fait tourner les sorties sur 3 VPN (gluetun : se-1, ch-1, nl-1) avec rotation quand un plafond par IP est atteint. 84 modèles gratuits, coût 0.

Le CT héberge aussi `zenfree-translator`, une brique de la même stack qui rend les modèles `muse-*` utilisables par n'importe quel client OpenAI-compatible.

## Placement

- LXC `233` `zenfree` sur `pve3`, `10.1.20.33` (VLAN 20), stack docker-compose dans `/opt/zenfree/deploy/`.
- Pool sur `:8020`, traducteur sur `:8099` (LAN uniquement, pas d'ingress Caddy).

## Pourquoi un traducteur

Le tier gratuit de Zen refuse le trafic qui ne vient pas d'un client opencode « reconnu » : sondes desde nos IP → `403 FreeTierError: OpenCode's free tier can only be used from within OpenCode`. La recette pour passer est connue (voir `9router`, projet tiers) : endpoint `/v1/responses`, `stream` forcé, `store: false`, ids `ses_`/`msg_` valides, en-têtes `x-opencode-*`, et le quartet d'outils `bash/glob/grep/read` avec `tool_choice: auto`.

Le pool seul ne fait pas cette traduction (il renvoie 500 sur `/v1/chat/completions` pour muse). Le traducteur l'applique **et** envoie le trafic par les proxies des conteneurs gluetun — c'est indispensable, une IP WAN est refusée alors que les sorties VPN passent.

## Traducteur (`zenfree-translator`, CT 233)

- systemd (dans le CT) : `/etc/systemd/system/zenfree-translator.service`, code `/opt/zenfree-translator/translator.py`, clé locale `/opt/zenfree-translator/.key` (600, à lire sur place), log `/opt/zenfree-translator/access.log` (`model=… code=… ms=… exit=…`, sans secrets ni corps).
- `muse-*` : `POST /v1/chat/completions` → `/v1/responses` amont via `http://<ip-gluetun>:8888`, avec l'empreinte complète. Rotation maison sur les 3 sorties (cap 150 requêtes/sortie puis cooldown 300s), un essai par sortie en cas d'échec transitoire (reconnexion VPN), `x-opencode-request` régénéré à chaque tentative.
- Autres modèles : simple relais vers le pool local (`127.0.0.1:8020`) — ils gardent la rotation et le catalogue du pool.
- `GET /v1/models` retransmis du pool. Concurrence : sémaphore à 3, sessions stables par conversation (dérivées du premier message → continuité + quota), 429 amont retransmis tel quel. Streaming SSE supporté.
- Note : `curl` via subprocess (et non `urllib`) parce que c'est la voie prouvée pour l'empreinte.

## Consommateurs

- Hermes (profil principal **et** profil `opencode`) : provider `translator` (`~/.hermes/plugins/model-providers/translator/` et `~/.hermes/profiles/opencode/plugins/model-providers/translator/`), `base_url http://10.1.20.33:8099/v1`, modèle `muse-spark-1.3-contributor-free`, clé `TRANSLATOR_API_KEY` dans le `.env` de chaque profil. Repli : `stealth/space-bunny-alpha` via OpenRouter.
- OpenWebUI (CT 131) : `http://10.1.20.33:8099/v1`, clé = `/opt/zenfree-translator/.key` sur le CT 233 (à lire sur place). Modèles : `muse-spark-1.3-contributor-free`, `space-bunny-free`, etc.
- Appels directs au pool `:8020` : seulement `space-bunny-free` passe ; muse passe par le traducteur.

## Pool (interface)

- Compatible OpenAI : `GET /v1/models`, `POST /v1/chat/completions`, `POST /v1/responses`.
- Auth : Bearer obligatoire (`auth.enabled: true`). Token dans `/opt/zenfree/deploy/zenfree-pool.docker.yaml` (clé `tokens`, ligne 9) — le lire sur place, ne jamais le copier en clair ailleurs.
- Les réponses sont gzippées : utiliser `curl --compressed`.

## Opérations

- Pool : config montée en bind (`/etc/zenfree/config.yaml`) → après modif, `docker restart zenfree` suffit.
- Traducteur : `systemctl restart zenfree-translator` (dans le CT). Code = fichier unique, pas de dépendance hors Python 3 + curl + docker (pour résoudre les IP gluetun).
- État des sorties : `docker logs zenfree` (`member unreachable` = sortie KO, `proxied … status=200` = OK) et `access.log` du traducteur pour ce qui passe par lui.
- Limites : quota gratuit par IP/session (d'où la rotation + les sessions stables), ~3 s par appel muse, pas designed pour de gros volumes.
