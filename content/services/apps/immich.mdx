Last synced with live infrastructure: **September 2026**.

Years of photos are the least replaceable data in this homelab — movies can be re-downloaded, pictures cannot. Immich is the self-hosted photo library that keeps them on local disks instead of somebody else's cloud, with mobile apps for backup and a web UI for browsing. Because the data is irreplaceable, the interesting question on this page is never the route (it is a plain Caddy proxy) but the storage and backup posture underneath it, both still to be fully documented.

## Placement

Immich runs as LXC `276` (`immich`) on `pve3` on the production VLAN, carrying the `10.1.20.76` tag with 6 GB of RAM.

## Ingress

Public traffic arrives as `immich.cleeryy.cloud` through Caddy toward `immich:2283`, currently with no SSO gate.

## Dependencies

Object storage and the database live on the LXC root disk (`local-lvm` on `pve3`), though the exact volume layout is not captured here. The guest is covered by the general PBS job, but the application-level backup posture for libraries, thumbnails, and ML data is still pending — guest restore and library restore are not the same thing.

## Failure impact

A `pve3` outage takes Immich down together with the rest of the production VLAN. The outage itself is ordinary; what makes it scary is the irreplaceable data sitting underneath it.

## Known gaps

For the least replaceable data in the homelab, the documentation is thinnest where it matters most: the exact volume holding the photo library is unconfirmed, there is no tested restore path for library plus database, and the dashboard sits open without SSO. Closing the first two is the highest-value documentation hour available on this site.
