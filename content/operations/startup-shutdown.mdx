Last synced with live infrastructure: **28/09/2026** (`qm`/`pct` config on both nodes).

After a power loss or a node reboot, the cluster should come back on its own — in dependency order, not all at once. The rule is simple: **every guest that runs is `onboot=1`, except the lab desktop `mint` (`10001`) which stays manual**. Stopped and parked guests stay off. Proxmox starts guests by ascending `startup order`, waiting `up=` seconds after a guest before starting the next one.

## Policy

| Scope | `onboot` | Notes |
|-------|----------|-------|
| All running VMs and LXCs on `pve1` and `pve3` | `1` | With `startup order` per the tables below |
| `mint` (`10001`, lab desktop) | `0` | Running, but manual — explicitly excluded from auto-start |
| `opnsense-slave` (`502`) | `0` | Stopped; manual failover only |
| Parked / stopped (`2242`, `6001`, `6002`, `4001`, `15001`, `15002`) | `0` | Stay off until needed |

## `pve3` boot order

Firewall first, then DNS and storage, then identity and ingress, then the monitoring plane, then the media chain (download → manage → serve), then everything else in parallel.

| Order | Guest(s) | `up` | Why this tier |
|-------|----------|------|---------------|
| `1` | `501` opnsense | 90s | Edge router — VLANs and WAN must exist before anything else |
| `2` | `553` technitium | 30s | Internal DNS — everything resolves through it |
| `3` | `127` truenas | 90s | Storage — pool import is slow, media depends on it |
| `4` | `130` authentik | 30s | SSO before the services behind it |
| `5` | `2010` caddy | 30s | Ingress before public services |
| `6` | `511` cloudflared-opnsense, `222` warpgate | — | Tunnel + bastion, parallel |
| `10` | `566` prometheus, `576` pve-exporter, `567` grafana, `577` scraparr, `129` wazuh, `578` pbs, `124` forgejo-runner, `205` obiwan | — | Monitoring / infra plane, parallel |
| `20` → `21` → `22` | `302` qbittorrent → `301` servarr → `300` jellyfin | 30s, 30s, — | Media chain in dependency order |
| `30` | `106`, `110`, `119`, `125`, `126`, `128`, `131`, `132`, `151`, `233`, `257`, `258`, `276`, `279` | — | App LXCs, parallel |

## `pve1` boot order

Database first, then the forge, then edge utilities, then the heavy Docker VMs staggered last so they don't hammer the host's I/O all at once.

| Order | Guest(s) | `up` | Why this tier |
|-------|----------|------|---------------|
| `1` | `112` postgresql | 30s | Shared database for Forgejo and friends |
| `2` | `108` alpine-docker | — | Docker host |
| `3` | `111` forgejo | 30s | Needs PostgreSQL up |
| `4` | `103` cloudflared, `105` nginxrpm, `107` elementsynapse | — | Edge / comms utilities |
| `5` | `101` rustypaste, `104` bentopdf, `109` docmost | — | Small apps |
| `6` | `200` nextcloud | 60s | Heaviest VM (12 GB) — boots alone, I/O settles after |
| `7` | `102` small-webapps, `202` beszel, `204` n8n | — | Remaining Docker hosts |

## Verify

- [ ] On the node hosting the guest: `grep -HE '^(onboot|startup):' /etc/pve/qemu-server/*.conf /etc/pve/lxc/*.conf`
- [ ] Every running guest shows `onboot: 1` + a `startup: order=N` line; `10001` shows `onboot: 0`.
- [ ] Stopped guests (`502`, `2242`, `6001`, `6002`, `4001`, `15001`, `15002`) show `onboot: 0` or no `onboot` line (default off).
- [ ] After any new guest is promoted to "runs permanently", set `onboot` + `startup order` the same day — e.g. `pct set <ctid> --onboot 1 --startup order=30`.
- [ ] After a real node reboot, confirm the order was respected (`journalctl -u pve-guests` on the node) and re-sync this page if tiers changed.

## Relation to restores

A whole-node restore boots in the same dependency order as above — firewall, ingress, identity/DNS, storage, then workloads. See [Backup & restore](/operations/backup-restore) for the restore checklists; this page defines the order those checklists boot into.
