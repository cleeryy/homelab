## Sites

The homelab spans two physical sites:

| Site ID | Location | Edge device | Role |
|---------|----------|-------------|------|
| `1` | mamie (server site) | OPNsense VM `401` on `pve3` | Carries the Proxmox cluster and all server workloads |
| `2` | home | Fortigate 81E (present, **not configured**) | Carries a Raspberry Pi running home-oriented services (Home Assistant, AdGuard Home, iSponsorBlock) |

The two sites are not yet interconnected at the routing layer. No site-to-site tunnel is configured today.

## Addressing scheme

All routed networks follow the convention:

```
10.<site>.<vlan>.0/24
```

The gateway for each subnet is `.1`. Site `1` is mamie; site `2` is reserved for home.

## VLAN plan — site 1 (mamie)

Defined on the OPNsense edge. The parent interface is `vtnet1` (OPNsense LAN-side virtual NIC); VLANs are tagged sub-interfaces `vlan0.<tag>`.

| VLAN | Tag | Name | CIDR | Gateway | DHCP |
|------|-----|------|------|---------|------|
| — | (untagged) | LAN | `10.1.1.0/24` | `10.1.1.1` | — |
| 10 | 10 | Admin | `10.1.10.0/24` | `10.1.10.1` | `.100`–`.199` (dnsmasq) |
| 20 | 20 | Production | `10.1.20.0/24` | `10.1.20.1` | — |
| 25 | 25 | Preproduction | `10.1.25.0/24` | `10.1.25.1` | — |
| 30 | 30 | IoT | `10.1.30.0/24` | `10.1.30.1` | — |
| 40 | 40 | Guest | `10.1.40.0/24` | `10.1.40.1` | `.10`–`.199` (dnsmasq) |
| 50 | 50 | Management | `10.1.50.0/24` | `10.1.50.1` | — |
| 60 | 60 | Home | `10.1.60.0/24` | `10.1.60.1` | `.10`–`.199` (dnsmasq) |

VLANs without a DHCP range are not currently serving DHCP from OPNsense.

## Edge — OPNsense (site 1)

- VM `401` on `pve3`, hostname `opnsense-mamini`, domain `internal`.
- WAN: `vtnet0`, DHCP from the upstream ISP, public IPv4 dynamic.
- LAN trunk: `vtnet1`, carries the untagged LAN plus all seven VLANs.
- DNS: Unbound on `:53` is the primary resolver; the `.internal` zone is forwarded to dnsmasq on `127.0.0.1:53053`, which serves DHCP-registered names. Upstream resolvers: `9.9.9.9`, `1.1.1.1`.
- Timezone `Europe/Paris`. NTP from the OPNsense pool.
- IDS/IPS: disabled. Traffic shaping: not configured. HA sync: not configured.

### Firewall posture (current)

Per-interface "allow all out" rules exist on the LAN, Admin, Production, WireGuard, and VPN interfaces. There is no inter-VLAN isolation policy in place yet. Several rules carry `[DEV]` or `TEMP` markers in their descriptions, indicating they are not the final intended state.

### Site-to-site VPN

IPsec is enabled in OPNsense but no Swanctl connections, locals, or remotes are defined — the site-to-site VPN between mamie and home is not yet configured.

## Edge — Fortigate (site 2)

A Fortigate 81E is present at the home site. It has not been configured. The Raspberry Pi at home currently sits directly on the upstream ISP router; its addressing is whatever the ISP CPE hands out.

## Legacy network on site 1

The Proxmox hosts and all Docker application VMs still run on the older flat network rather than on the new VLAN plan:

| Segment | CIDR | Status |
|---------|------|--------|
| Management LAN | `192.168.1.0/24` | In use by `pve1`, `pve3`, OPNsense `net0`, NPM, all Docker VMs |
| Internal / routed | `10.0.0.0/24` (at least) | In use on `vmbr1` (`pve3`) via OPNsense `net1` |

Host gateway for both Proxmox nodes is `192.168.1.1`. The new VLAN plan above lives on the OPNsense edge but the workloads are not migrated onto it.

## Ingress

Two reverse-proxy VMs are present on `pve1`:

- `ubuntu-nginx-proxy-manager` (`100`) — Nginx Proxy Manager.
- `ubuntu-nginxrpm` (`105`) — second reverse-proxy VM.

Both are visible on the management LAN. The canonical ingress split is not confirmed; this is tracked in the [migration plan](/architecture/migration-plan).

A `cloudflared` LXC (`103`) on `pve1` provides outbound tunneling for selected services.

## Beszel hostname mismatches

Two Docker hosts report a system hostname `ntfy` in Beszel while their system label is different:

- `n8n` host — label `n8n`, system hostname `ntfy`.
- `web-apps` host — label `web-apps`, system hostname `ntfy`.

The cause is not documented. The mismatch is recorded so that operators reading Beszel do not misidentify hosts.
