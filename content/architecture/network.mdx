## Sites

The homelab spans two physical sites:

| Site ID | Location | Edge device | Role |
|---------|----------|-------------|------|
| `1` | mamie (server site) | OPNsense VM `501` on `pve3` | Carries the Proxmox cluster and all server workloads |
| `2` | home | Fortigate 81E (present, **not configured**) | Carries a Raspberry Pi running home-oriented services (Home Assistant, AdGuard Home, iSponsorBlock) |

The two sites are not yet interconnected at the routing layer. No site-to-site tunnel is configured today.

## Addressing scheme

All routed networks follow the convention:

```
10.<site>.<vlan>.0/24
```

The gateway for each subnet is `.1`. Site `1` is mamie; site `2` is reserved for home. Proxmox tags mirror this: `20.x` = `10.1.20.x` (production), `25.x` = `10.1.25.x` (preproduction), `50.x` = `10.1.50.x` (management), `1.x` = legacy `192.168.1.x`.

## Edge — OPNsense (site 1)

- VM `501` `opnsense` on `pve3` (16 GB RAM), firmware `26.1.11_10`.
- WAN: `vtnet0`, static `192.168.1.250/24`, gateway `192.168.1.1` (ISP CPE). The firewall sits behind the ISP box — **double NAT** for inbound traffic.
- LAN trunk: `vtnet1` (`10.1.1.1/24`), carries the untagged LAN plus all seven VLANs.
- DNS: Unbound on `:53` is the primary resolver. Override: `internal.cleeryy.cloud` → `10.1.50.53` (Technitium). DHCP served by dnsmasq (Admin `.100`–`.199`, Guest `.10`–`.199`, Home `.10`–`.199`).
- Plugins: `os-crowdsec` 1.0.12 and `os-netbird` 1.3_3. Suricata (IDS) is **running**.
- Gateways `WAN_GW` (`192.168.1.1`) and `AIRVPN_GW` (`10.128.0.1`) both report online.
- IPv6: not configured on any production interface (loopback only).

### Firewall posture (current)

Per-interface "allow all" rules still exist on LAN, Admin, Production, Preproduction, WireGuard, and NetBird interfaces. Several rules carry `[DEV]` or `TEMP` markers — not the final intended state. There is still no inter-VLAN isolation policy. New since June: an `INTERNAL` group with policy routing (outbound via `AIRVPN_GW`) followed by a kill-switch block rule, plus logged WAN rules for WireGuard (`udp/51920`) and NetBird P2P (`udp/51825`).

### NAT port forwards (current)

| Service | WAN | Target | Notes |
|---------|-----|--------|-------|
| Caddy HTTP | `:80/tcp` | `10.1.20.10:80` | Ingress |
| Caddy HTTPS | `:443/tcp` | `10.1.20.10:443` | Ingress |
| Warpgate SSH | `:22/tcp` | `10.1.20.22:2222` | SSO bastion |
| Palworld | `:8211/udp`, `:8212/udp`, `:27015/udp` | `10.1.20.143` | Game server |

Outbound: hybrid mode — `INTERNAL` group traffic NATs via the AirVPN interface (with kill-switch), NetBird traffic keeps a static-port WAN mapping.

### Site-to-site VPN

IPsec has no connections defined — the site-to-site VPN between mamie and home is still not configured.

## Remote access — WireGuard road-warrior (site 1)

OPNsense runs a WireGuard server (`wg0`):

| Setting | Value |
|---------|-------|
| Listen | `udp/51920` on WAN |
| Tunnel network | `10.1.90.0/24` |
| Server address | `10.1.90.1` |
| Peer DNS pushed | `94.140.14.14`, `94.140.15.15` (AdGuard public DNS) |

Three peers are configured (`m4-air` → `.90.3`, `iphone15` → `.90.2`, `windaube` → `.90.4`); all showed offline at the last observation. Public keys and pre-shared keys are stored in the OPNsense configuration backup and are deliberately not reproduced here.

## Privacy egress — AirVPN client (site 1)

OPNsense runs a second WireGuard client (`wg1`, `AirVPN-NL3`):

- Address `10.130.184.82/32` (+ IPv6 ULA), endpoint online, keepalive 15 s. Lifetime counters at last observation: ~14 GB RX / ~353 GB TX.
- The `INTERNAL` interface group routes outbound traffic via `AIRVPN_GW`, with a kill-switch block rule directly below it — if the tunnel drops, that traffic is blocked rather than leaking to WAN.

See [Services > Connectivity](/services/core/connectivity) for the service-level view.

## Mesh — NetBird (site 1)

NetBird runs on OPNsense (`wt0`, `100.121.135.95/16`) with 7 peers online at the last observation, plus a VPS-based peer and endpoints on production hosts (Caddy network, Palworld host, `pve1`). WAN rule allows NetBird P2P (`udp/51825`). See [Services > Connectivity](/services/core/connectivity).

## Edge — Fortigate (site 2)

A Fortigate 81E is present at the home site. It has not been configured. The Raspberry Pi at home currently sits directly on the upstream ISP router; its addressing is whatever the ISP CPE hands out.

## Legacy network on site 1

Proxmox management and the legacy Docker application VMs still run on the flat network:

| Segment | CIDR | Status |
|---------|------|--------|
| Management LAN | `192.168.1.0/24` | In use by `pve1`, `pve3`, OPNsense WAN (`192.168.1.250`), legacy Docker VMs, NAS (`192.168.1.16`), TrueNAS (`192.168.1.74`) |

Host gateway for both Proxmox nodes is `192.168.1.1`. The old `vmbr1` (`10.0.0.0/24`) and `vmbr2` segments are gone: `vmbr2` no longer exists on `pve3`.

## Ingress

Canonical ingress is **Caddy** (LXC `2010` at `10.1.20.10`, also tagged on legacy `.205`):

- Wildcard TLS via Cloudflare DNS-01 for `cleeryy.cloud`, `*.cleeryy.cloud`, `*.home.cleeryy.cloud`.
- Public zone (`sites/public/`): user services — `homelab`, `dokploy`, `authentik`, `code` (behind Authentik `forward_auth`), `wazuh`, `nextcloud`, `n8n`, `immich`, `jellyfin`/`jellyseerr`, `affine`, `guacamole`, `truenas`, `dashboard`, `search`, `sure`, `chat`, `matrix`, and more. Full list lives in `/etc/caddy/sites/` on the Caddy host.
- Private zone (`sites/private/`, `*.home.cleeryy.cloud`): `pbs` (`:8007`), `dns` (Technitium `:5380`), `proxmox`/`pve1`/`pve3` (`:8006`), `nas`, `adguard`, `ha`, plus service-internal routes.
- Nginx Proxy Manager (VM `100`) has been decommissioned. `ubuntu-nginxrpm` (`105`) still runs on `pve1`; its role is tracked in the [migration plan](/architecture/migration-plan).

A `cloudflared` LXC (`103`) on `pve1` plus `cloudflared-opnsense` (`511`) on `pve3` provide Cloudflare tunnel egress for selected services.

Two Docker hosts report a system hostname `ntfy` in Beszel while their system label is different:

- `n8n` host — label `n8n`, system hostname `ntfy`.
